# Crystal Boy package (FFXI Offline), 2026-10-28

A Game Boy emulator inside FFXI (Ashita 4 addon), real custom items and key items, and a server module that turns
the Gobbiebag quests into a Crystal Boy questline with rewards. Built and tested on the desktop server (Phoenix fork of
LandSandBoat, Ashita 4, era DAT pack). This file is written for whoever installs it on another server, person or AI agent.

## What is in the zip

| Folder / file | Goes to | What it is |
|---|---|---|
| `addon/crystalboy/` | `<Ashita>\addons\crystalboy\` | The addon (Lua), with the 32-bit gambatte libretro core in `cores\` |
| `addon-config/rewards.lua` | `<Ashita>\config\addons\crystalboy\rewards.lua` | Completion rules (play time per game) |
| `server/crystalboy_quests.lua` | `<server>\modules\custom\lua\` | Gobbiebag rework, rewards, +1% exp, GM commands |
| `kit/install_crystalboy_items.py` | the kit folder (e.g. `C:\FFXISOLO`) | Writes items/key items into the game DATs and the server SQL |
| `kit/install_crystalboy.py` | the kit folder | Copies the addon into Ashita, adds the autoload line |
| `kit/assets/crystalboy/*.png` | `<kit>\assets\crystalboy\` | 32x32 item icons (used by the item installer) |
| `kit/dev/crystalboy-tests/` | optional | Stand-in tests (texlua, gcc for `fakecore.c`) |
| `roms/` | `<Ashita>\config\addons\crystalboy\roms\` | The owner's own ROM dumps (do not share) |
| `saves/` | `<Ashita>\config\addons\crystalboy\saves\<Character>\` | The owner's saves, already named after their ROMs |
| `reference/crystalboy_items.sql` | (generated by the installer) | For reference: the SQL the installer writes |

## Horro's Visit (the Dragon Quest X event)

The seasonal event (`server/horros_visit.lua`, copied to `<server>\modules\custom\lua\`) has its own five games.
Talking to a town slime (Slarin in Southern San d'Oria, Sludge in Bastok Markets, Ultra Slime in Windurst Woods)
gives every character **8100 Crystal Boy and 8105 Dragonland I once**; the other four parts are prizes at **15 slime
coins each**. The ROMs ship in `roms\` with the Jueno ones and are installed and replaced the same way.

| Item | Game (ROM header title) | Finished after | On finishing |
|---|---|---|---|
| 8105 Dragonland I | Dragonland 1 (DRAGONLAND 1) | 8 h | +1% exp while Signet is active |
| 8106 Dragonland II | Dragonland 2 (DRAGONLAND 2) | 8 h | +1% exp while Signet is active |
| 8107 Dragonland III | Dragonland 3 (DRAGONLAND 3) | 8 h | +1% combat and magic skill-up rate while Signet is active |
| 8108 Dragonland IV | Dragonland 4 (DRAGONLAND 4) | 8 h | +1% combat and magic skill-up rate while Signet is active |
| 8109 Dragonland V | Dragonland 5 (DRAGONLAND 5) | 8 h | +1% combat and magic skill-up rate while Signet is active |

These five have no Memory key items: the client's key-item file is full (all 3,192 ids are named), so the server
records each finished part on the character from the addon's claims file (`[CB]DL1`-`[CB]DL5` character variables,
refreshed at most every five minutes while something is still missing, or immediately with `!cbdl`) and adds the
bonus while Signet is active, exactly like the Memories above.

## Requirements on the target machine
- LandSandBoat-based server with the interaction/quest framework and `modules\init.txt` (Phoenix fork tested).
  Uses `xi.module.modifyInteractionEntry`, `xi.module.registerCommand`, `Module:addOverride`.
- Ashita 4 with LuaJIT FFI, `d3d8`, `imgui` addon libraries (standard).
- Python 3 on Windows with **Pillow** (`pip install pillow`) and the **mariadb** connector (`pip install mariadb`).
- English FFXI client. Tested with the Phoenix **era DAT pack** (item records 0x1400 bytes). The installer checks the
  layout (Page from the Dragon Chronicles record, icon header, key item rebuild) and refuses to write if it differs.

## Install (in order)
1. Unzip anywhere. Put `kit\*` into the kit folder (the folder that has `config.json`).
2. `config.json` in the kit folder must have: `ffxi_client_dir`, `server_dir`, `ashita_dir`, `ashita_boot`,
   `db_user`, `db_pass`, `db_name` (optional `db_host`, `db_port`). The item installer also accepts `--client` and
   `--server`; the database login always comes from `config.json`.
3. **Close the game**, then (PowerShell, run as the user who can write to Program Files):
   ```powershell
   cd C:\FFXISOLO; python install_crystalboy_items.py
   ```
   It backs up `ROM\118\107.DAT`, `ROM\118\109.DAT`, `ROM\175\35.DAT` once into `<kit>\backups\crystalboy-dat\`,
   writes only empty or own slots, writes `modules\custom\sql\crystalboy_items.sql`, lists it in `init.txt`, applies it.
   `--status` shows the state, `--restore` puts the original files back. Re-run after reinstalling an era DAT pack.
4. Addon: copy `addon\crystalboy` to `<Ashita>\addons\crystalboy` (or run `python install_crystalboy.py --core <path to cores\gambatte_libretro.dll>`,
   which also adds `/addon load crystalboy` to the boot script). Copy `addon-config\rewards.lua`, `roms\*`, and `saves\*` into
   `<Ashita>\config\addons\crystalboy\` (saves go in `saves\<CharacterName>\`).
5. Server: copy `server\crystalboy_quests.lua` to `<server>\modules\custom\lua\` and add this line to `modules\init.txt`:
   ```
   custom/lua/crystalboy_quests.lua
   ```
6. Restart the server (no rebuild: Lua and SQL only).

## Machine-specific things to check
- **Where the server finds the completion records:** `crystalboy_quests.lua` reads
  `<ashita_dir>\config\addons\crystalboy\claims\<CharacterName>\claims.lua`, with `ashita_dir` taken from
  `C:\FFXISOLO\config.json` (fallback `C:\Ashita-v4beta-main`). If the kit or Ashita live elsewhere on the laptop,
  change `ashitaDir()` near the middle of the file. The server and the game must be on the same PC.
- Item ids 8100-8109 and key items 1634, 2605, 2841, 2716 must be free on that server and client (the installer checks the client side).
- The Gobbiebag rework replaces the quests' sections completely; it duplicates the era fame values (3,4,5,5,6,6,7,7,8,9)
  that Phoenix's era module sets.
- The 1% exp bonus overrides `xi.experiencePoints.calculate` and calls the previous version, so it stacks with other modules (squad, era exp).

## Using it
- Items must be in the **main inventory**. Use the Crystal Boy (opens the window) or a Recollection (starts its game)
  from the item menu: the addon catches the use packet, so nothing is used up. Without the addon the server says
  "Unable to use item" (no item scripts on purpose).
- While the window has focus it takes all keyboard and controller input (FFXI gets nothing); click the game to give it back.
  Controls panel in the window; defaults: arrows, X = A, Z = B, Enter = Start, Backspace = Select, Space = fast forward,
  F5/F7 = save/load state; Xbox and PlayStation pads supported.
- Commands: `/cb`, `/cb list`, `/cb stop`, `/cb ff`, `/cb save|load [1-3]`, `/cb scale`, `/cb speed`, `/cb done`, `/cb record`, `/cb snap`, `/cb diff`.
- GM-only (GM level 1+): `!cbfame <1-9>`, `!cbfinish [8101-8104] [reset]`, plus the normal `!additem`.

## Known open item
- One access-violation crash was seen in the addon's per-frame code (`d3d_present`) when starting FFA DX with a save on the
  desktop (Ashita then unloads all addons). Not reproduced since. This build writes a step trace to
  `<Ashita>\config\addons\crystalboy\trace.txt` and `trace_last.txt`; if it crashes, the last line names the step.
  To switch the trace off later, set `on = false` at the top of `addon\crystalboy\cb\trace.lua`.

## Item DAT lessons (if you extend it)
- Item icon tags must be a known category (`item    ` + `item%04d`), and biClrImportant must be 32, or the client's Items menu crashes.
- Key items: `ROM\175\35.DAT` is a `d_msg` file, 0x40 header, fixed 0x2BC entries XOR 0xFF,
  entry = [id, category, "", "", name, plural, description].
- The server consumes every non-equipment usable item on use (`CCharEntity::OnItemFinish`); that is why the addon blocks packet 0x37.
